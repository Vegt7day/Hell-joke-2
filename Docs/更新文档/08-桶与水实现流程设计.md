# 桶与水实现流程设计（基于现有子弹/开关实现）

本文档用于规划两个新场景：

- 可交互物：`桶`
- 配套子弹：`水`

目标是复用现有工程里已经稳定的两类机制：

1. 玩家子弹命中对象后调用 `take_damage(...)`
2. 机关对象通过 `AnimationPlayer` 驱动状态切换与表现

---

## 1. 现有实现调研结论

### 1.1 玩家子弹命中链路（`ink.gd`）

现有玩家子弹（`entities/player/bullet/ink.gd`）核心流程：

1. `CharacterBody2D` 子弹在 `_physics_process` 中 `move_and_collide`
2. 命中后进入 `_handle_collision(...)`
3. 如果碰撞体实现了 `take_damage`，则执行：
   - `collider.take_damage(damage)`
4. 子弹自身禁用碰撞并播放消失动画，延时 `queue_free`

这意味着新“桶”只要实现 `take_damage(damage_amount, attacker = null)`，就能无缝被玩家墨弹触发。

### 1.2 开关受击模式（`开关.gd`）

`system/可交互物/开关.gd` 的受击逻辑可直接借鉴：

- `bullet_trigger_enabled`：是否允许子弹触发
- `damage_threshold`：伤害阈值
- `is_processing`：状态切换期间防重入
- 统一通过状态应用函数驱动动画与状态落地

“桶”的受击也建议保留这套门槛与防抖参数，减少重复触发导致的动画冲突。

## 2. 新增场景职责划分

### 2.1 桶（建议：`system/可交互物/桶.tscn` + `桶.gd`）

职责：

- 接收玩家子弹伤害（`take_damage`）
- 维护桶内是否有水（状态机）
- 负责播放三个动画片段：
  - `with_water`（常态）
  - `lose_water`（失水）
  - `add_water`（回水）
- 在 `lose_water` 开始时生成一个 `水` 实例

### 2.2 水（建议：`entities/player/bullet/水.tscn` + `water.gd`）

职责：

- 作为垂直下落投射物（有重力）
- 拥有与玩家墨弹一致的碰撞层语义（按项目子弹层设置）
- 生命周期动画：
  - 创建动画（spawn）
  - 下落循环动画（fall）
  - 命中后消失动画（disappear）
- 对可受伤对象调用 `take_damage`

---

## 3. 桶状态机设计

## 状态定义

- `WITH_WATER_IDLE`：有水常态，循环 `with_water`
- `LOSING_WATER`：正在放水，播放 `lose_water`，并在起始帧生成水
- `ADDING_WATER`：正在回水，播放 `add_water`

## 关键规则

1. 初始进入 `WITH_WATER_IDLE`
2. 第一次受击（在 `WITH_WATER_IDLE`）：
   - 切到 `LOSING_WATER`
   - 立刻生成 `水`
3. `lose_water` 结束后自动进入 `ADDING_WATER`
4. `add_water` 结束后自动回到 `WITH_WATER_IDLE`
5. 若 `ADDING_WATER` 期间再次受击：
   - 不打断当前动画
   - 仅记录一次“已受击”事件用于统计/反馈（可选）
   - 当前轮次完成后仍回到 `WITH_WATER_IDLE`，不自动进入下一次 `LOSING_WATER`

这满足需求中“被击打进入 lose/add 一轮流程；若中途再次击打，也要先完整走完本轮并回到闲置态”的时序控制。

---

## 4. 桶受击流程（时序）

## 输入

- 玩家墨弹命中调用：`take_damage(damage_amount, attacker = null)`

## 处理步骤

1. 检查 `bullet_trigger_enabled`
2. 检查 `damage_threshold`
3. 若桶处于 `WITH_WATER_IDLE`：
   - 进入 `LOSING_WATER`
   - 开播 `lose_water`
   - 同步生成 `水`（在动画开始即生成）
4. 若桶处于 `ADDING_WATER`：
   - 记录一次“受击但不打断”标志（可选，用于表现/日志）
   - 不改变本轮流程终点：`add_water` 完成后回 `WITH_WATER_IDLE`
5. 若桶处于 `LOSING_WATER`：
   - 忽略或合并请求（推荐忽略，避免刷出过多水）

---

## 5. 水子弹流程（时序）

## 创建阶段

1. 桶实例化 `水` 场景
2. 设置出生位置（桶出水口 `Marker2D`）
3. 设置初始速度（`Vector2.ZERO`）
4. 播放 `spawn` 动画

## 下落阶段

1. `spawn` 动画结束后切 `fall` 动画
2. 每帧应用重力：`velocity.y += gravity * delta`
3. 使用 `move_and_collide` 或 `move_and_slide` 垂直下坠

## 命中阶段

1. 发生碰撞后：
   - 禁用碰撞体
   - 若目标有 `take_damage`，传递伤害
   - 播放 `disappear`
2. 消失动画结束 `queue_free`

## 6. 节点结构建议

### 6.1 桶场景

- `StaticBody2D (Barrel)`
  - `Sprite2D`
  - `CollisionShape2D`
  - `AnimationPlayer`
  - `Marker2D (WaterSpawnPoint)`  # 水生成位置

### 6.2 水场景

- `CharacterBody2D (WaterProjectile)` 或 `Area2D`
  - `Sprite2D`
  - `CollisionShape2D`
  - `AnimationPlayer`
  - （可选）`AudioStreamPlayer`

说明：若优先对齐现有 `ink.gd`，建议用 `CharacterBody2D`，可直接复用移动与碰撞处理范式。

---

## 7. 动画与脚本同步点

为避免状态错乱，建议使用以下同步策略：

1. 桶：
   - 由脚本切状态并调用 `animation_player.play(...)`
   - 通过 `animation_finished` 回调驱动下一状态
2. 水：
   - `spawn -> fall -> disappear` 全由脚本明确切换
   - 不依赖单纯定时器判断命中结束

---

## 8. 与现有系统兼容建议

1. **伤害接口兼容**
   - 桶与水命中目标都使用 `take_damage(...)`
2. **碰撞层复用**
   - 水使用与玩家墨弹一致的 `collision_layer` / `collision_mask`
3. **防重入**
   - 桶保留 `is_processing` 或状态枚举防抖
4. **性能与数量控制**
   - 若担心刷出过多水，可加 `max_active_water` 或冷却时间

---

## 9. 实现顺序建议（落地步骤）

1. 新建 `桶.tscn`，先做静态 `with_water` 播放
2. 实现 `桶.gd.take_damage` + 状态机（不生成水）
3. 新建 `水.tscn` + `water.gd`，实现 `spawn/fall/disappear`
4. 在桶的 `lose_water` 起始接入水实例化
5. 联调碰撞层与伤害
6. 最后补充音效与特效

---

## 10. 验收清单

1. 墨弹命中桶时能进入 `lose_water`
2. `lose_water` 开始时必定生成 1 个水
3. 水先播放创建动画，再进入下落动画
4. 水下落时可命中并造成伤害
5. 命中后播放消失动画并销毁
6. 桶在 `add_water` 结束后回 `with_water`
7. `add_water` 期间再次受击，不会打断当前动画，且本轮结束后仍回 `with_water`（不自动进入下一轮）
