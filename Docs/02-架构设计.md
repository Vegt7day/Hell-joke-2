# 02 - 架构设计

## 架构分层

本作未严格采用 MVC，但可按职责粗分为三层理解：

| 层次 | 主要内容 | 典型路径 |
|------|-----------|-----------|
| **表现层** | Sprite2D、AnimationPlayer、UI（TextureProgressBar、DialogueBox）、Dialogic 布局 | `entities/**`, `system/ui/`, Dialogic 插件 |
| **逻辑层** | 玩家移动/状态、敌人射击、关卡流程、交互、对话触发 | `student.gd`, `teacher.gd`, `world.gd`, `interactable.gd` |
| **数据层** | 全局 `Stats`（生命/墨水）、`world_states` 字典、`user://data.sav` JSON、Dialogic `.dtl/.dch` | `system/class/stats.gd`, `game.gd`, `assets/` |

**设计取舍**：玩家属性集中在自动加载 `Game` 下的 `PlayerStats`，UI 与玩家脚本通过 `Game.player_stats` 与 `Stats` 的 **signal** 同步，避免 UI 直接写业务数值的分散逻辑。

---

## 主要节点树组织方式

### 1. 运行时根结构（概念）

- `/root` 下除引擎节点外，包含自动加载：`Dialogic`、`Game`（`CanvasLayer`）、`DialogicRegistry`。
- **`Game` 节点树**（`game.tscn`）：高 `layer` 的 `CanvasLayer`，子节点含用于转场的 `ColorRect` 与 `PlayerStats`（`Stats` 场景实例）。

```text
Game (CanvasLayer, game.gd)
├── ColorRect      # 全屏淡入淡出
└── PlayerStats    # Stats 实例，全局玩家数值
```

### 2. 关卡场景（`world.tscn` 等）

由 `WorldController`（`world.gd`）驱动：根为 `Node2D`，子节点包含 `teacher`、`player`、门区域、`UI/DialogueBox` 等。关卡脚本通过 `@onready` 与可选 `NodePath` 绑定编辑器摆放的节点。

### 3. 玩家实体

`CharacterBody2D` 为主体，子节点包含动画播放器、音效、`Marker2D`（发射点 / Dialogic 锚点）、交互图标等；子弹实例化后加入 **`get_parent()`**（一般为关卡根），与玩家解耦。

## 场景继承关系

Godot 4 中「继承」主要体现在：

- **PackedScene 实例化**：如 `ink_bullet_scene.instantiate()`、`bullet_scene.instantiate()`。
- **脚本继承**：`Teleporter` **extends** `Interactable`，重写 `interact()` 并 `super()` 调用基类日志与信号。

```gdscript
# system/可交互物/Teleporter.gd
class_name Teleporter
extends Interactable

func interact() -> void:
	super()
	Game.change_scene(path, { "entry_point": entry_point })
```

**说明**：`Interactable` 与 `ContactTrigger` 为平行设计（均用 `Area2D` + 玩家注册列表），并非同一继承树；统一时可考虑抽象共同接口（如 `IInteractable` 风格的虚方法或小型基类）。

## 模块间通信方式

### 1. 自动加载（全局引用）

任何脚本可通过 `Game`、`Dialogic`、`DialogicRegistry` 名称访问：

```gdscript
# entities/player/real player/student.gd
@onready var stats: Stats = Game.player_stats
```

### 2. 信号（Signal）

- **`Stats`**：`health_changed`、`ink_changed` → `status_panel.gd` / `boss_health_bar.gd` 更新 UI。
- **`Interactable`**：`interacted`；教师 **`teacher_time_out`** 等关卡结束条件。
- **Dialogic**：`WorldController` 将 `dialog.connect("event_end", ...)`，并用 `DialogicUtil.autoload().signal_event.connect(receive)` 接收时间线内发出的自定义信号名（如 `"允许移动"`）。

```gdscript
# system/levels/world.gd（节选）
func receive(sig: String):
	if sig == "允许移动" and player:
		player.enable_action("move_left")
		player.enable_action("move_right")
```

### 3. 约定优于配置的方法调用

关卡通过 `has_method` / `call` 与玩家、教师协作（如 `disable_action`、`start_attacking`），降低硬编码类型依赖，但牺牲了静态检查。

### 4. 组（Groups）

教师 `add_to_group("enemies")`；`WorldController.to_dict` / `from_dict` 遍历 `get_nodes_in_group("enemies")` 做简单持久化同步。

### 5. 已知不一致点（改进项）

存档逻辑已统一使用 **`/root/DialogicRegistry`**（常量 `DIALOGIC_REGISTRY_PATH`）；历史误写 `DialogueRegistryManager` 已移除。

## 场景切换与暂停策略

`Game.change_scene` 在切换前 `tree.paused = true`，Tween 使用 `TWEEN_PAUSE_PROCESS` 以便在暂停下仍能跑完淡变；切场景后恢复 `paused = false`。

```gdscript
# system/globals/game/game.gd（节选）
tree.paused = true
var tween := create_tween()
tween.set_pause_mode(Tween.TWEEN_PAUSE_PROCESS)
tween.tween_property(color_rect, "color:a", 1, 0.2)
await tween.finished
tree.change_scene_to_file(path)
```

**设计意图**：保证淡出在暂停世界中仍可见、可执行，避免未定义行为。
