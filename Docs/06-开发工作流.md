# 06 - 开发工作流

## 代码组织规范

### 当前约定

- **按功能分目录**：`entities`（谁）、`system`（关卡/UI/全局）、`assets`（数据与媒体）。  
- **脚本与场景共置**：同一功能子目录内 `.gd` / `.tscn` 配对，降低查找成本。  
- **自动加载仅用于横切关注点**：`Game`、`Dialogic`、`DialogicRegistry`。

### 建议补充（团队规模扩大时）

1. 增加 `scripts/autoload/` 或 `core/` 命名空间目录，区分「引擎插件」与「自研核心」。  
2. 对 `WorldController` 级别脚本补充 **顶部模块注释**（依赖场景结构、必要子节点列表）。  
3. 将魔法字符串（Dialogic 信号名 `"允许移动"` 等）提取为 `const` 文件，便于重构。

## 命名约定

| 类别 | 现状 | 建议 |
|------|------|------|
| 类名 | `Player`、`Interactable`、`ContactTrigger` 等 | PascalCase，避免与场景内 `node name` 冲突 |
| 中文 `class_name` | 已迁移为英文（如 `ContactTrigger`） | 新代码避免使用中文标识符作为 `class_name` |
| 私有意图 | 商鞅脚本用 `_current_state` | 下划线前缀表示内部状态，保持一致 |
| 场景目录 | `system/scene/` | 标题与 loading 场景目录（已统一命名） |

**示例（良好的导出命名）**：

```gdscript
# system/levels/world.gd
@export var level_duration: float = 5.0
@export var teacher_intro_timeline: String = "teacher_intro"
@export var door_area_path: NodePath
```

## 测试策略

### 现有内容

- `test/test_teacher.tscn`：用于教师相关联调；嵌入了 `game.tscn` 以保持与正式运行时一致的全局环境。

### 建议增强

1. **单元级**：为 `Stats.to_dict/from_dict`、`DialogicRegistry.save_registry/load_registry` 编写 GUT 或原生轻量测试场景（无需引入重框架即可用「断言场景」手动跑）。  
2. **集成级**：最小化关卡副本，仅包含地面 + 玩家 + 假人木桩，验证 `ink` 伤害与层掩码。  
3. **存档回归**：构造样例 `data.sav` JSON，加载后断言 `player_stats.health` 与场景名。

### 手动测试清单（示例）

- 新游戏 → 对话结束 → 能否移动 / 攻击。  
- `Esc` 存档 → 退出 → 读档 → 位置与墨水是否恢复。  
- 教师攻击中 Boss 血条显隐是否与 `teacher.gd` 一致。

## 性能考量

### 已启用项

- `project.godot`：`2d/run_on_separate_thread=true`，有利于物理与主线程重叠（需注意线程安全：尽量通过信号回主线程修改 UI）。  
- `run/max_fps=240` 与 `loading.gd` 中 `Engine.max_fps = 60` 可能**互相覆盖**——以最后执行的脚本为准，建议在单一入口（如 `Game._ready`）统一帧率策略。

```gdscript
# system/scene/loading.gd（节选）
Engine.max_fps = 60
```

### 热点路径

- **玩家 `_physics_process`**：避免每帧 `print`（`Player` 相关逻辑中高频日志发布前应移除或加日志级别）。  
- **教师 `shoot()`**：使用 `await` 链，若关卡销毁需确保异步不访问已释放节点（可在 `is_instance_valid` 或 `is_inside_tree` 守卫）。

### 渲染

- 视口基础分辨率 `640x360`，`canvas_items` 拉伸；像素风资源保持 **`default_texture_filter` 与素材像素对齐** 即可。

### 可选优化

| 方向 | 说明 |
|------|------|
| 粒子 / 特效 | 限制同屏粒子数，使用 `one_shot` |
| 碰撞体 | 简单形状优先于复杂多边形 |
| 对象池 | 同 `05-资源管理.md` |

## 版本控制与协作

- **忽略**：开发者本地 `.godot/` 缓存通常应 `.gitignore`（以项目 `.gitignore` 为准）。  
- **插件升级**：升级 Dialogic 前提交独立分支，跑一遍标题 → 关卡 → 对话全链路。  
- **文档**：本 `Docs/` 系列与代码变更同步更新「关键类」「存档格式」章节。

## 代码示例：安全的异步射击

在可能被 `queue_free` 的节点中使用 `await` 时，建议模式：

```gdscript
await get_tree().create_timer(0.3).timeout
if not is_inside_tree():
	return
# 继续创建子弹等逻辑
```

减少竞态导致的空引用。

## 提交与 Code Review 检查点

1. 新增资源是否更新 `project.godot` 或 Dialogic 配置。  
2. 是否误用 `/root/` 下错误节点名。  
3. 新场景是否实现 `to_dict`/`from_dict`（若需要存档）。  
4. 输入映射是否同步 `project.godot` 的 `[input]`。  
5. 是否在 `_exit_tree` 中断开非 `CONNECT_ONE_SHOT` 的持久信号（`BossHealthBar` 已有良好示例）。

```gdscript
# system/ui/boss_health_bar.gd（节选）
func _exit_tree():
	if stats and stats.health_changed.is_connected(update_health):
		stats.health_changed.disconnect(update_health)
```

保持该模式可降低泄漏与二次连接风险。
