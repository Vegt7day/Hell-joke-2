# 03 - 核心系统分析

## 角色控制系统

### 两套玩家实现并存

| 脚本 | `class_name` | 特点 |
|------|--------------|------|
| `entities/player/student/student.gd` | `Student` | 双 `AnimationPlayer`（上/下半身）、跳跃延迟与 Coyote Time、墨水攻击与恢复、较复杂的 `disable_action` 输入门控 |
| `entities/player/real player/student.gd` | `Player` | **显式状态机**（`PlayerState` 枚举）、召唤商鞅（`summon`）、单精灵翻转 |

**移动核心**（两脚本共性）：`CharacterBody2D` + `move_and_slide()`，水平 `move_toward` 逼近目标速度，竖直重力来自 `ProjectSettings`。

```gdscript
# entities/player/real player/student.gd（节选 — 状态切换）
func change_state(new_state: PlayerState):
	if new_state == current_state:
		return
	exit_state(current_state)
	previous_state = current_state
	current_state = new_state
	state_timer = 0.0
	enter_state(current_state)
```

### 交互栈

玩家维护 `interacting_with: Array[Interactable]` 与 `接触触发_with`；每帧若按下 `interact`，对**栈顶**调用 `interact()`（后进先出）。

```gdscript
# entities/player/student/student.gd（节选）
if Input.is_action_just_pressed("interact") and interacting_with:
	interacting_with.back().interact()
```

**改进点**：多重叠区域时 LIFO 是否符合设计需产品确认；可改为优先级或最近距离选择。

## 敌人生成 / AI 系统

### 教师（`teacher.gd`）

- **非寻路 AI**：站桩发射「蚊子」子弹；用 `Timer` 控制射击周期。
- **自动扣血**：`_process` 中累加时间，按间隔减少自身 `teacher_stats.health`，归零时发出 `teacher_time_out` 等信号，供关卡判定。
- **与 UI 绑定**：`_ready` 中若血条节点存在则 `set_stats(teacher_stats)`。

```gdscript
# entities/enemy/teacher/teacher.gd（节选）
func start_attacking(interval: float = 2.0):
	shoot_interval = interval
	is_attacking_enabled = true
	shoot_timer.start()
	start_auto_damage()
```

### 商鞅 NPC（`商鞅.gd`）

- **`ShangYang`**：`MODE`（剧情 / 召唤）+ 内部 `STATE`；召唤模式下 `take_damage` 与血量阈值驱动形态动画。
- 由 `Player.execute_summon()` 实例化后加入场景并 `switch_to_summoned_mode()`。

**说明**：敌人「生成」多为编辑器摆放 + 关卡内 `PackedScene.instantiate()`；无通用对象池。

## 物理 / 碰撞系统

### 碰撞层语义

`project.godot` 中 `[layer_names]` 定义了 2D 物理层用途，例如：

- `Environment`、`Player`、`Enemy`、`player_bullet`、`机关`、`提示`、`Enemy_bullet`、`交互`

### 玩家子弹 `ink.gd`

使用 `move_and_collide`；命中后对 `take_damage` 的目标造成伤害，再播放消失动画并 `queue_free()`。

### 敌人子弹 `蚊子.gd`

支持 **附着**到玩家碰撞层（代码中 `body_layers & 2` 检测 Player 层）：附着后每帧跟随目标并持续 `take_damage`，由 `stick_timer` 结束生命周期。

```gdscript
# entities/enemy/bullet/蚊子.gd（节选）
if stick_to_target and collider:
	var body_layers = collider.collision_layer
	if body_layers & 2:
		stick_to_collider(collider)
```

**改进点**：用层常量或 `PhysicsServer2D` 层掩码枚举替代魔数 `2`，并在注释中与 `project.godot` 层索引对齐说明。

## UI 管理系统

### 玩家 HUD：`status_panel.gd`

默认将 `stats` 指向 `Game.player_stats`，订阅 `health_changed` / `ink_changed`，用 `TextureProgressBar` 显示比例；生命条支持「缓动条」Tween。

```gdscript
# system/ui/status_panel.gd（节选）
func _ready() -> void:
	if not stats:
		stats = Game.player_stats
	stats.health_changed.connect(update_heath)
	stats.ink_changed.connect(update_ink)
```

### Boss 血条：`boss_health_bar.gd`

通过 `call_deferred("initialize_with_retry")` 解决节点就绪顺序问题；可 `set_stats` 由教师脚本注入。

### 关卡内文案框

`WorldController` 直接操作 `$UI/DialogueBox` 下控件显示系统提示，与 Dialogic 对话框并存——属于**轻量 UI 与插件 UI 双轨**。

## 音频 / 视觉效果系统

- **音频**：各实体挂载 `AudioStreamPlayer`（跳跃、行走、攻击、射击等），在状态切换或动画事件中 `play()`。
- **转场视觉**：`Game` 的 `ColorRect` alpha Tween。
- **动画**：以 `AnimationPlayer` 为主驱动角色表现；商鞅等使用 `animation_finished` 回调推进状态。

**改进点**：可为音乐 / SFX 分 Bus，并在 `project.godot` 的 Dialogic `audio/channel_defaults` 与游戏内 `AudioStreamPlayer` 之间统一规范。

## 保存 / 加载系统

### 存档路径与格式

- 路径常量：`user://data.sav`
- 内容：`JSON.stringify` 包裹字典，包含 `world_states`、`character_registry`、`stats`、当前场景路径、`player` 位置与方向等。

```gdscript
# system/globals/game/game.gd（节选）
var data := {
	"world_states": world_states,
	"character_registry": character_registry_data,
	"stats": player_stats.to_dict(),
	"scene": scene.scene_file_path,
	"player": { "direction": player_direction, "position": { "x": player_position.x, "y": player_position.y } }
}
var json := JSON.stringify(data)
FileAccess.open(SAVE_PATH, FileAccess.WRITE).store_string(json)
```

### 场景状态

- 切场景前若 `current_scene.has_method("to_dict")`，将字典存入 `world_states[场景基名]`。
- `WorldController` 的 `to_dict` / `from_dict` 示例：记录 `enemies` 组内节点路径，读档时销毁不在列表中的敌人。

### 读档流程

`load_game()` 解析 JSON → 恢复 `world_states` 与 `player_stats` → 调用 `change_scene(data.scene, { position, direction })`。

**已知问题**：

1. `DialogueRegistryManager` 路径错误可能导致 `character_registry` 始终为空（见 `02-架构设计.md`）。  
2. `new_game()` 传入的 `"init"` 闭包未被 `change_scene` 使用，开局重置可能不完整。  
3. `Stats` 中 `ink` 的 setter 使用 `clampi` 限制浮点墨水，存在类型语义问题（见 `04-关键类说明.md`）。

### `world_2.gd` 与读档

`world_2.gd` 的 `update_player` 使用 `has_node("player")`，而脚本顶部引用为 `$Student`；若读档依赖 `update_player`，可能**无法定位节点**。应统一为实际节点名或使用组/`%` 唯一名。

---

## 小结

核心循环为：**全局 Stats + Game 场景流 + 关卡控制器 + Dialogic 时间线信号**。优先修复存档注册表路径与 `world_2` 玩家节点名，可显著提升存档与第二关体验的一致性。
