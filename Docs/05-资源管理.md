# 05 - 资源管理

## 资源文件组织方式

### `assets/` 目录

| 子区域 | 内容 |
|--------|------|
| **`assets/资源总库/`** | **图像 / 音频 / 字体 / Dialogic 工程与散装时间线** 的统一根；子目录编号见 [`总文档/素材目录与引用说明.md`](总文档/素材目录与引用说明.md) |
| `assets/资源总库/12_Dialogic工程/Dialogic/` | 角色 `.dch`、`level2/` 下时间线等 |
| `assets/资源总库/12_Dialogic工程/*.dtl` | 根级散装时间线 |
| `assets/资源总库/12_Dialogic工程/bubble.tres` | Dialogic 样式 `bubble` |
| `assets/资源总库/01_图像_背景/`、`02_图像_地图/` | 关卡与地图贴图 |
| `assets/资源总库/11_字体/` | 如 `DejaVuSans.ttf` |
| `assets/资源总库/10_音频/` | `.mp3` / `.wav` 与对应 `.import` |

**配置绑定**：`project.godot` 的 `[dialogic]` 将逻辑名映射到 `资源总库/12_Dialogic工程/...`，编辑器与运行时共用。

```ini
# project.godot（节选）
[dialogic]
directories/dch_directory={
"character": "res://assets/资源总库/12_Dialogic工程/Dialogic/character.dch",
"中学生": "res://assets/资源总库/12_Dialogic工程/Dialogic/中学生.dch",
...
}
layout/style_list=["res://assets/资源总库/12_Dialogic工程/bubble.tres"]
```

### `entities/` 与 `system/`

- **实体场景**：`*.tscn` 与同名或约定名 `*.gd` 相邻存放（如 `student.tscn` + `student.gd`）。  
- **关卡**：`world.tscn`、`world_2.tscn` 与 `world.gd`、`world_2.gd`。  
- **可复用组件**：`system/class/stats.tscn` 作为子场景被 `game.tscn` 实例化。

### 引擎导入资源

所有对 `res://` 二进制资源的引用均伴随 `.import` 文件（由 Godot 管理）。**版本库策略**：通常提交 `.import` 以保证团队导入参数一致；大资源可结合 Git LFS（本仓库是否启用以 `.gitattributes` 为准）。

## 动态加载策略

### 1. 场景实例化（运行时主要方式）

子弹、召唤物、Dialogic 对话节点均在运行时 `instantiate()` 后加入场景树：

```gdscript
# entities/player/real player/student.gd（节选）
var shangyang = shangyang_summon_scene.instantiate() as ShangYang
get_parent().add_child(shangyang)
```

**设计决策**：子节点挂在关卡根（`get_parent()`）而非玩家节点下，便于统一物理层与清理范围。

### 2. `Game.change_scene` 使用文件路径字符串

```gdscript
tree.change_scene_to_file(path)
```

属于 **整场景替换**；适合关卡粒度。小范围 UI 弹窗仍建议用 `add_child` 或 `CanvasLayer` 管理而非频繁换场景。

### 3. Dialogic 时间线

- `WorldController` 使用 **`Dialogic.start(timeline_name)`**（逻辑名，由插件解析）。  
- `到区域触发对话.gd` 中同时存在 `load(dialogue_timeline)` 与 `Dialogic.start(dialogue_timeline)` 分支准备，实际以 `Dialogic.start` 为主路径。

### 4. 区域触发器中的资源检查

```gdscript
if not ResourceLoader.exists(dialogue_timeline):
	print("时间线文件不存在: ", dialogue_timeline)
	return
```

避免无效路径导致运行时硬错误。

## 内存管理考虑

### 短期对象

- **子弹**：生命周期由 `lifetime` 计时器与碰撞逻辑结束，最终 `queue_free()`。  
- **Dialogic 对话节点**：`event_end` / `timeline_ended` 后 `queue_free()`。

### 长期存活

- **`Game` 与 `PlayerStats`**：随游戏进程常驻；`new_game()` 应重置 `world_states` 与属性（当前需确认 `init` 回调是否生效）。  
- **DialogicRegistry**：地图存 `NodePath`；目标节点释放后会于 `get_character_node` 中清理无效项。

```gdscript
# dialogic_registry.gd（节选）
if not node or not is_instance_valid(node):
	character_map.erase(character_id)
	return null
```

### 附着子弹的引用

`蚊子.gd` 附着到 `stick_target` 时，若目标提前 `queue_free()`，应依赖 `is_instance_valid` 检查（代码中部分路径已使用）；需防止每帧对已释放对象调用方法——当前在 `_physics_process` 开头有 `stick_target` 校验，**维护时保持该习惯**。

## 资源命名规范（现状与建议）

### 现状

- **中英文混用**：目录 `可交互物`、时间线 `什么？！.dtl` 等，体现内容主题但在跨平台工具链中可能出现编码问题（Windows 终端已观察到乱码）；可交互脚本类名已统一为 `ContactTrigger` / `AutoTeleporter` 等英文标识。  
- **Dialogic 键名**：`中学生`、`老教师` 与 `DialogicRegistry` 的字符串一致，属于**约定式 API**。

### 建议规范

1. **路径与文件名**：优先 ASCII（`props/door_red.tscn`），显示名放翻译或资源内 `display_name`。  
2. **时间线 / 角色 ID**：保持与 `register_character` 第一个参数一致，集中定义为 `const` 或 `enum` 映射。  
3. **场景内节点**：对脚本强依赖的节点使用编辑器 **唯一名称（%）**，并保持关卡内玩家根节点命名为 `player` 等与 `Game` / `WorldController` 约定一致。  
4. **组名**：`"enemies"`、`"player"` 等与 `project.godot` 层名一同写入单例 `GameConstants` 脚本。

## 改进点汇总

| 主题 | 建议 |
|------|------|
| 大资源 | 背景音、整图背景考虑压缩格式与 `2D` 纹理导入裁切 |
| 预加载 | 关卡开始前 `ResourceLoader.load_threaded_request` 预加载下关常用 PackedScene（可选） |
| 对象池 | 高频子弹可池化以降低实例化抖动（需权衡实现成本） |
| 存档 | JSON 外可校验版本号字段 `save_format_version`，便于迁移 |

## 代码示例：导出场景引用

在编辑器中拖拽分配 `PackedScene`，避免硬编码路径分散：

```gdscript
# entities/enemy/teacher/teacher.gd（节选）
@export var bullet_scene: PackedScene
```

配合 `if not bullet_scene: return` 在运行时给出明确日志，有利于 QA 复现配置遗漏。
