# 架构优化待办清单

本文档由《01-项目概述》至《06-开发工作流》六份架构文档交叉整理而成，按优先级给出可执行的修复与优化项。

## P0 - 关键缺陷（阻碍核心功能，必须优先修复）

*   **问题描述**：`game.gd` 通过 `get_node_or_null("/root/DialogueRegistryManager")` 访问注册表，但 `project.godot` 中自动加载节点名为 **`DialogicRegistry`**，导致存档时无法调用 `save_registry()`、读档时无法 `load_registry()`，新开游戏时也无法 `clear_all()`。问题在《02-架构设计》《03-核心系统分析》中已指出。

*   **影响**：`character_registry` 在 `user://data.sav` 中恒为空或无法恢复；读档后 Dialogic 依赖的全局角色锚点可能失效；新游戏可能残留旧注册路径，引发对话立绘/气泡错位或空引用。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\globals\game\game.gd`

*   **修改建议**：将所有 `"/root/DialogueRegistryManager"` 统一改为 `"/root/DialogicRegistry"`（或与 `project.godot` 中 `[autoload]` 实际名称完全一致）。示例：

```gdscript
# save_game()、load_game()、new_game() 内统一写法
const REGISTRY_PATH := "/root/DialogicRegistry"

func save_game() -> void:
	var registry = get_node_or_null(REGISTRY_PATH)
	if registry and registry.has_method("save_registry"):
		character_registry_data = registry.save_registry()
```

读档分支同样使用 `REGISTRY_PATH`；`new_game()` 里清理注册表处一并替换。若团队更倾向保留「Manager」命名，可选方案 B：在编辑器中将自动加载条目改名为 `DialogueRegistryManager` 并同步 `project.godot`（改动面更大，不推荐除非对外 API 已依赖该名）。

*   **验证方法**：运行游戏 → 进入关卡完成 `DialogicRegistry` 注册 → `Esc` 存档 → 检查 `user://data.sav` 中 `character_registry` 是否为非空字典 → 退出重启读档 → 触发依赖注册表的对话，确认无「角色未注册」类日志。

---

*   **问题描述**：`world_2.gd` 中 `@onready var player: Player = $Student`，但 `update_player()` 使用 `has_node("player")` 与 `$player`，与场景中实际节点名不一致。问题在《03-核心系统分析》中已指出。

*   **影响**：切换到 `world_2.tscn` 后，读档或 `Game.change_scene(..., { position, direction })` 无法把玩家放到正确位置与朝向，表现为出生点错误或未移动。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\levels\world_2.gd`
    *   （若存在）`d:\items\godot\hell_joke_2\文字地狱重制版\system\levels\world_2.tscn` — 建议将玩家根节点在编辑器中设为唯一名 `%Player` 或统一命名为 `player`，与 `WorldController.update_player` 约定一致

*   **修改建议**：优先采用「与 `world.gd` 一致」的节点名策略。示例 A — 改脚本以使用已有 `@onready` 成员：

```gdscript
func update_player(position: Vector2, direction: int = 1) -> void:
	if player and is_instance_valid(player):
		player.global_position = position
		if player.has_method("set_direction"):
			player.set_direction(direction)
		elif "direction" in player:
			player.direction = direction
	else:
		push_warning("world_2: 玩家节点无效")
```

示例 B — 在 `world_2.tscn` 中将 `Student` 节点重命名为 `player`，并保留 `class_name Player` 的脚本，使 `Game.change_scene` 内 `get_node("player")` 在跨场景逻辑中也可解析（需同时核对 `save_game()` 里对 `"player"` 子节点的依赖）。

*   **验证方法**：在 `world_2` 中存档 → 读档 → 确认玩家出现在存档坐标且朝向正确；从其他场景 `change_scene` 到 `world_2` 并传入 `entry_point`/`position` 参数各测一次。

*   **问题描述**：`new_game()` 向 `change_scene` 传入的 `params` 中包含 `"init"` 闭包，但 `change_scene` 从未读取或执行该键，导致开局重置 `world_states` 与 `player_stats` 的逻辑可能不生效。问题在《01-项目概述》《02-架构设计》中已指出。

*   **影响**：新游戏流程可能未清空旧 `world_states`，或未把 `PlayerStats` 恢复为 `default_player_stats`，表现为「新游戏却带着旧关卡状态或数值」的偶现缺陷。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\globals\game\game.gd`

*   **修改建议**（二选一或组合）：

    1. **在 `new_game()` 开头显式重置**，不依赖 `params`：

```gdscript
func new_game() -> void:
	var registry = get_node_or_null("/root/DialogicRegistry")
	if registry and registry.has_method("clear_all"):
		registry.clear_all()
	world_states.clear()
	player_stats.from_dict(default_player_stats)
	change_scene("res://system/levels/world.tscn", {})
```

    2. **或在 `change_scene` 末尾**统一处理：`if params.has("init") and params.init is Callable: params.init.call()`（需注意在切场景前/后何时机调用更符合语义，避免访问已释放节点）。

*   **验证方法**：先打进度产生 `world_states` → 返回标题选新游戏 → 确认血量墨水为默认值、无上一局残留敌人状态。

---

*   **问题描述**：`Stats` 中 `ink` 为 `float`，但 setter 使用 `clampi(v, 0, max_ink)`，整型钳制与浮点语义不符，且 `to_dict` 未序列化当前 `ink` 值。问题在《04-关键类说明》中已指出。

*   **影响**：墨水小数被截断或边界行为异常；若后续在 `to_dict`/`from_dict` 中补充 `ink`，当前 setter 仍可能造成数值抖动。存档主数据虽在 `player_stats.to_dict()` 中携带 `health/max_health/max_ink`，但**当前** `ink` 字段未写入字典，读档后墨水仅依赖场景初始化逻辑，与真实游玩状态可能不一致。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\class\stats.gd`

*   **修改建议**：

```gdscript
@onready var ink: float = max_ink:
	set(v):
		v = clampf(v, 0.0, max_ink)
		if is_equal_approx(ink, v):
			return
		ink = v
		ink_changed.emit()

func to_dict() -> Dictionary:
	return {
		"max_health": max_health,
		"health": health,
		"max_ink": max_ink,
		"ink": ink,
	}

func from_dict(dict: Dictionary) -> void:
	max_health = dict.get("max_health", max_health)
	health = dict.get("health", health)
	max_ink = dict.get("max_ink", max_ink)
	ink = dict.get("ink", max_ink)
```

*   **验证方法**：游戏中消耗墨水 → 存档 → 读档 → 确认墨水条与数值一致；边界测试 `ink` 略大于 `max_ink` 的赋值是否被钳制。

## P1 - 重要改进（影响可维护性与扩展性）

*   **问题描述**：目录名为 `system/scence/`，「scence」为拼写错误，与常见 `scene` 不一致。问题在《01-项目概述》《06-开发工作流》中已指出。

*   **影响**：新成员路径易错；全文搜索、外部工具与 CI 脚本路径易漏改。

*   **修改文件**：
    *   将文件夹 `d:\items\godot\hell_joke_2\文字地狱重制版\system\scence\` 重命名为 `d:\items\godot\hell_joke_2\文字地狱重制版\system\scene\`（或 `scenes`）
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\project.godot`（若主场景使用 `res://` 路径而非仅 UID，需同步）
    *   所有引用 `res://system/scence/` 的 `.tscn`、`.gd`（当前至少含 `loading.tscn`、`title_screen.tscn` 及其中 `ext_resource`）

*   **修改建议**：在 Godot 内用「依赖项更新」或 IDE 全局替换 `system/scence` → `system/scene`，重载工程后运行主菜单与 loading 场景冒烟测试。

*   **注意事项**：主场景若仅保存为 UID，重命名文件夹后 UID 仍解析，但 **ext_resource 路径** 仍会写磁盘路径，必须全局替换；Git 记录建议使用单独提交「rename + path fix」便于 bisect。

---

*   **问题描述**：`Student`（`entities/player/student/student.gd`）与 `Player`（`entities/player/real player/student.gd`）两套横版逻辑并行存在，无共同基类，功能重叠（移动、攻击、交互、墨水、输入门控）。问题在《03-核心系统分析》《04-关键类说明》中已指出。

*   **影响**：修复输入或物理 bug 需改两处；新能力（如格挡）易只加一侧导致关卡差异。

*   **修改文件**：视决策而定，可能涉及  
    `entities/player/student/student.gd`  
    `entities/player/real player/student.gd`  
    新建如 `entities/player/player_movement.gd`（`RefCounted` 或组合节点）

*   **修改建议**：召开短技术决策（ADR）：**保留双角色**（剧情关用 Student、重制关用 Player）则至少抽出共享 `MovementConfig` + `InkWeapon` 模块；**统一为 Player** 则迁移关卡引用并删除或归档 `Student`。

*   **注意事项**：全局搜索 `Student`、`class_name Player`、场景内脚本挂载；Dialogic 锚点 `Marker2D` 名称在两侧场景中需对齐。

*   **问题描述**：`class_name 接触触发` 使用中文标识符，部分外部工具、日志与生成文档可读性差。问题在《04-关键类说明》《06-开发工作流》中已指出。

*   **影响**：IDE 补全、静态分析、非中文环境协作成本上升。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\可交互物\接触触发.gd`
    *   所有类型注解为 `接触触发` 的脚本（如 `Student`/`Player` 中的 `Array[接触触发]`）

*   **修改建议**：将 `class_name` 改为 `ContactTrigger`（或 `AreaContactTrigger`），场景 `.tscn` 中脚本引用不变则类名变更后 Godot 会自动重绑；GDScript 中数组类型改为 `Array[ContactTrigger]`。

*   **注意事项**：全项目搜索 `接触触发` 与 `register_接触触发` 方法名；方法名若保留中文拼音混排，可逐步改为 `register_contact_trigger` 并做一次兼容封装 `@deprecated`。

*   **问题描述**：`Game.save_game()` 仅当 `scene.has_node("player")` 时记录位置，与 `world_2` 使用 `Student` 节点名等场景不一致时，存档中 `player.position` 可能长期为 `(0,0)`。与《03-核心系统分析》中关卡差异问题同源。

*   **影响**：部分关卡读档后玩家落点错误。

*   **修改文件**：
    *   `d:\items\godot\hell_joke_2\文字地狱重制版\system\globals\game\game.gd`

*   **修改建议**：用组名解析玩家，例如约定所有关卡玩家根节点在组 `player`：`get_tree().get_first_node_in_group("player")`，或遍历子节点 `if node is Player or node is Student`（若保留双脚本，可抽接口 `has_method("get_direction")` 统一处理）。

*   **注意事项**：需在 `world.tscn`、`world_2.tscn` 等中为玩家节点勾选对应组。

## P2 - 优化与增强（提升代码质量与性能）

*   **问题描述**：《06-开发工作流》指出 `project.godot` 中 `run/max_fps=240` 与 `loading.gd` 内 `Engine.max_fps = 60` 可能互相覆盖；`Student` 墨水恢复路径存在高频 `print` 风险。

*   **影响**：帧率策略不可预期；发布构建下日志 IO 造成轻微卡顿。

*   **修改建议**：在单一入口（如 `Game._ready` 或主菜单 `_ready`）根据菜单项「性能/省电」设置 `Engine.max_fps`；将调试 `print` 改为 `push_warning` 或 `OS.is_debug_build()` 包裹。

*   **风险评估**：低（行为可测）；注意主机平台对帧率上限的期望。

---

*   **问题描述**：`蚊子.gd` 等使用魔数碰撞层位掩码（如 `body_layers & 2`）对照《05-资源管理》建议。

*   **影响**：调整 `project.godot` 层顺序后易静默失效。

*   **修改建议**：定义 `const LAYER_PLAYER := 2` 或在导出变量中配置 `player_physics_mask`，与项目设置文档同步。

*   **风险评估**：低；需回归子弹附着与穿墙。

---

*   **问题描述**：`tip_开.gd` 中 Dialogic 实际调用大量注释占位，与《03-核心系统分析》中「双轨 UI」并存，易造成「提示关未真正弹出对话」的维护盲区。

*   **影响**：功能不完整或行为与注释描述不一致。

*   **修改建议**：对齐 `到区域触发对话.gd` 的实现，统一调用 `Dialogic.start(...)` 并处理 `event_end`/`timeline_ended`。

*   **风险评估**：中（需对照 Dialogic 版本 API）。

---

*   **问题描述**：缺少 `export_presets.cfg` 与自动化测试（《01》《06》）。

*   **影响**：发布链路依赖本机手动配置；回归靠人工。

*   **修改建议**：在仓库中提交脱敏后的导出预设模板；为 `Stats`、`DialogicRegistry` 与 `Game.change_scene` 增加最小 GUT 或「断言场景」手工清单。

*   **风险评估**：低（流程类）。
