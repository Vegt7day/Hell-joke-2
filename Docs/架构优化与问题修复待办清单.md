# 架构优化待办清单

本文档由《01-项目概述》至《06-开发工作流》六份架构文档交叉整理而成，按优先级给出可执行的修复与优化项。

**进度说明**：截至当前分支，**P0 四项**及 **P1-1～P1-4** 已在代码中落实（含移除旧 `Student`、统一为 `Player`，以及 `ContactTrigger` / `AutoTeleporter` 英文化）；**P2** 仍为待办。

## P0 - 关键缺陷（**已全部完成**）

### P0-1 `DialogicRegistry` 自动加载路径

*   **状态**：**已完成**
*   **原问题**：`game.gd` 使用 `/root/DialogueRegistryManager`，与 `project.godot` 中 `[autoload]` 名称 **`DialogicRegistry`** 不一致，导致注册表无法随存档读写、`new_game` 无法 `clear_all`。
*   **已落实**：`system/globals/game/game.gd` 增加 `DIALOGIC_REGISTRY_PATH`，`save_game` / `load_game` / `new_game` 统一通过该常量访问。
*   **验证**：存档 JSON 中 `character_registry` 非空；读档后对话锚点正常。

### P0-2 `world_2.gd` 与玩家节点引用

*   **状态**：**已完成**
*   **原问题**：`@onready` 使用 `$Student` 与 `update_player` 内 `has_node("player")` / `$player` 不一致，读档或带参切场景时无法正确放置玩家。
*   **已落实**：`system/levels/world_2.gd` 改为 `@onready var player: Player = $player`，`update_player` 与 `world.gd` 一致使用 `player_node` 及 `is_instance_valid`。
*   **验证**：在 `world_2` 存档/读档及 `change_scene` 传入坐标后位置与朝向正确。

### P0-3 `new_game()` 与 `change_scene` 的 `"init"` 参数

*   **状态**：**已完成**
*   **原问题**：`params["init"]` 闭包从未被 `change_scene` 调用，新游戏可能未清空 `world_states` 或未恢复默认 `PlayerStats`。
*   **已落实**：`new_game()` 在调用 `change_scene` **之前**显式 `world_states.clear()`、`player_stats.from_dict(default_player_stats)`、清理 `DialogicRegistry`，并移除无效的 `"init"` 传参。
*   **验证**：产生进度后选「新游戏」，数值与关卡状态为干净开局。

### P0-4 `Stats.ink` 类型与序列化

*   **状态**：**已完成**
*   **原问题**：`ink` setter 误用 `clampi`；`to_dict` / `from_dict` 未包含当前墨水值。
*   **已落实**：`system/class/stats.gd` 使用 `clampf` 与 `is_equal_approx`；`to_dict` 含 `ink`；`from_dict` 使用 `dict.get("ink", max_ink)` 兼容旧存档。
*   **验证**：消耗墨水后存档再读档，墨水与 UI 一致。

### P1-4 `Game.save_game()` 玩家节点定位（**已完成**）

*   **状态**：**已完成**
*   **原问题**：依赖 `scene.has_node("player")` / `get_node("player")`，节点名不一致时存档中玩家坐标恒为 `(0,0)`。
*   **已落实**：
    *   `game.gd`：`PLAYER_SAVE_GROUP`、`_find_player_node_under_scene()`（当前场景子树内、浅层优先查找带 `"player"` 组的 `Node2D`），`save_game()` 使用该结果读取位置与朝向。
    *   `Player` 的 `_ready()` 首行 `add_to_group("player")`，与 `tip_开.gd` 等约定一致；**一般无需**在 `world.tscn` / `world_2.tscn` 上再手动勾选组（非上述脚本驱动的玩家根节点除外）。
*   **验证**：`world` / `world_2` 等关卡存档后 `data.sav` 中 `player.position` 非零（玩家在树内且已 `_ready` 后存档）。
