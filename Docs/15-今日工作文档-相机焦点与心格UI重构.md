# 今日工作文档：相机焦点与心格 UI 重构

## 1. 今日目标

本次工作聚焦 4 个方向：

1. 新增 **摄像头焦点 Area2D 对象**：玩家进入区域时，摄像头焦点向「玩家到区域中心」方向偏移到 `k` 比例位置。
2. 将生命显示重构为 **心格系统**：1 颗心 = 2 点生命，支持最大心数扩展、受伤/恢复动画、横向扩展、最大上限。
3. 重构墨水显示为 **攻击格系统**：1 格代表 1 次攻击消耗，直观显示可攻击次数。
4. 给玩家相机增加 **移动/跳跃/落地前瞻**：X/Y 前瞻合成总前瞻，使镜头更有引导性。

## 3. 设计方案

## 3.1 相机焦点 Area2D

### 功能描述

创建一个可放置在关卡中的 Area2D（例如 `camera_focus_area.gd`）：

- 玩家进入后，相机目标点从玩家位置，向区域中心偏移：
  - `focus_target = player_pos + (area_center - player_pos) * k`
  - 其中 `0 < k < 1`
- 相机以可调速度向该目标平滑移动。
- 玩家离开区域时，相机回到普通跟随模式。

### 建议导出参数

- `@export_range(0.01, 0.99) var focus_k: float = 0.4`
- `@export var camera_move_speed: float = 220.0`
- `@export var blend_in_seconds: float = 0.25`（可选）
- `@export var blend_out_seconds: float = 0.2`（可选）
- `@export var one_shot: bool = false`（可选，触发一次后失效）

### 状态建议

- `is_player_inside: bool`
- `tracked_player: Node2D`
- 可选：给 Player 挂一个“外部焦点请求”接口，避免多个系统互相争夺相机。

## 3.2 生命 UI：心格系统（1 心 = 2 血）

### 核心规则

- `max_health` 与 `health` 仍保留为数值主源（Stats）。
- 显示层按 2 点血为单位映射到心格：
  - `max_hearts = ceil(max_health / 2.0)`
  - `current_hearts_fill` 按半心/整心显示（如果要支持半心表现）
- 当 `max_health` 提升时，心格数量向右扩展。

### 最大上限建议

- `MAX_HEART_CAP`（例如 20 心）
- 当 `max_hearts > MAX_HEART_CAP` 时按上限截断显示（数值层仍可保留上限同步策略）

### 动画建议

你已说明会提供“心的图片和精灵动画”，建议每个心格节点具有状态动画：

- `full`（满心）
- `half`（半心，可选）
- `empty`（空心）
- `damage`（扣心过程）
- `heal`（回心过程）

推荐结构：

- `HeartContainer`（`HBoxContainer`）
  - `HeartCell` x N（场景复用）

### 更新策略

- 监听 `stats.health_changed`
- 比较旧值与新值，逐格播放差异动画（而不是整条重绘）

## 3.3 墨水 UI：攻击格系统

### 核心规则

- 每次攻击消耗 `ATTACK_INK_COST`（当前已有常量）
- 可攻击次数：
  - `max_attack_slots = floor(max_ink / ATTACK_INK_COST)`
  - `current_attack_slots = floor(ink / ATTACK_INK_COST)`

### 展示建议

- 与心格类似使用 `HBoxContainer` 横向格子
- 格子状态：
  - `ready`（可用）
  - `empty`（不可用）
  - 可选 `recovering`（回墨过程中闪烁）

### 注意

- 墨水是连续值，格子是离散值；需接受“格跳变”。
- 如果想避免视觉跳变，可对 UI 增加短暂缓动但不改变实际判定。

## 3.4 玩家相机前瞻（X+Y 合成）

### X 前瞻

- 玩家向右移动：镜头向右偏移 `lookahead_x`
- 玩家向左移动：镜头向左偏移 `lookahead_x`
- 停止时平滑回 0

### Y 前瞻

- 上升（跳跃）阶段：向上前瞻 `lookahead_y_up`
- 到达顶点后开始下落：切换到向下前瞻 `lookahead_y_down`（落地预判）
- 落地后回归常态（或保留小幅地面前瞻）

### 合成方式

- 最终偏移：`camera_lookahead = Vector2(x_lookahead, y_lookahead)`
- 与其他系统（如受击震动、焦点区偏移）叠加时，建议分层：
  - `base_follow + lookahead + focus_bias + shake_offset`

### 建议导出参数

- `lookahead_x_distance`
- `lookahead_y_up_distance`
- `lookahead_y_down_distance`
- `lookahead_lerp_speed_x`
- `lookahead_lerp_speed_y`
- `fall_threshold_velocity`（判定明显下落）

## 5. 验收标准（DoD）

1. 进入相机焦点区域后，镜头按 `k` 规则稳定偏移，离开后恢复。
2. 生命显示为心格，1 心=2 血；受伤/恢复有对应动画。
3. 增加最大生命后，心格向右扩展，且受上限控制。
4. 墨水显示为离散攻击格，随可攻击次数变化。
5. 玩家左右移动有 X 前瞻；起跳上移有上前瞻；最高点下落有落地前瞻。
6. 相机综合偏移无明显抖动/打架（与受击震动、焦点偏移兼容）。

---

## 6. 风险与注意事项

1. **相机控制权冲突**：焦点区、前瞻、震动可能相互覆盖，必须统一合成入口。
2. **UI 性能**：心格和墨水格频繁重建会抖动，建议对象池或差量更新。
3. **状态边界**：死亡/复活/读档时需重置相机偏移与 UI 缓存。
4. **参数过大导致眩晕**：前瞻距离/速度必须保守起步。
