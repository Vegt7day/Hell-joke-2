## 二、开发阶段

### Phase 0：基础设施（1-2天）

**目标**：搭建所有后续系统共用的底层框架

#### 0.1 标签系统

**新建文件**：`system/globals/tag_system.gd`（Autoload）

```gdscript
# 给任意 Node 添加/移除/查询标签
TagSystem.add_tag(node, "FLAMMABLE")
TagSystem.has_tag(node, "FLAMMABLE")
TagSystem.remove_tag(node, "FLAMMABLE")
TagSystem.get_nodes_with_tag("BURNING")  # 返回所有带该标签的节点
```

**实现要点**：
- 用 Dictionary 存储 `{node_rid: [tags]}`，节点 tree_exiting 时自动清理
- 提供信号 `tag_added(node, tag)` / `tag_removed(node, tag)` 供其他系统监听

#### 0.2 状态效果管理器

**新建文件**：`system/globals/status_effect_manager.gd`（Autoload）

```gdscript
# 给任意 Node 施加/移除状态
StatusEffectManager.apply(node, "burning", {duration=5.0, damage_per_sec=2.0})
StatusEffectManager.remove(node, "burning")
StatusEffectManager.has_effect(node, "burning")
```

**实现要点**：
- 每个状态是一个 Resource（`resources/effects/*.tres`）
- 管理器维护 `{node: {effect_id: StatusInstance}}`
- 每帧 `_process` 更新所有状态计时器
- 状态到期时自动移除并发出信号

#### 0.3 状态效果 HUD

**新建文件**：`system/ui/status_effects_hud.gd` + `.tscn`

**位置**：CanvasLayer 1，状态面板下方

**实现要点**：
- 监听 StatusEffectManager 的信号
- 每个活跃状态显示一个小图标 + 剩余时间
- 最多显示 8 个，超出时显示 "+N"

#### 0.4 问号检查系统升级

**修改文件**：`system/ui/inspect_detector.gd` + `system/ui/inspect_popup.tscn`

**目标**：问号模式点击任意对象（粒子、场景物体、玩家、召唤物、敌人）时，弹窗显示完整信息，特殊词条可交互查看。

**弹窗显示顺序（从上到下）**：

```
┌──────────────────────────────┐
│  ❤ 15/20                     │  ← 血量（有血量的对象才显示）
│  商鞅                        │  ← 名字
│  嘲讽吸引仇恨的召唤物         │  ← 介绍/描述
│                              │
│  状态：                       │
│  [燃烧] [易燃] [流血]         │  ← 当前状态标签（特殊词条）
│                              │
│  标签：                       │
│  [FLAMMABLE] [WET]           │  ← 当前标签（特殊词条）
└──────────────────────────────┘
```

**特殊词条交互**：
- **鼠标悬停超过 1 秒**：弹出 tooltip 显示该词条的详细解释
- **鼠标左键单击**：同样弹出 tooltip（两种方式等效）
- tooltip 内容从 `TagSystem` / `StatusEffectManager` 的描述字段读取

**实现要点**：

1. **Inspectable 接口**：所有可被检查的对象实现统一接口
   ```gdscript
   # inspectable_interface.gd
   func get_inspect_name() -> String
   func get_inspect_description() -> String
   func get_inspect_health() -> Vector2i  # (current, max)，无血量返回 (0,0)
   func get_inspect_tags() -> Array[StringName]  # 当前标签列表
   func get_inspect_statuses() -> Array[StringName]  # 当前状态效果列表
   ```

2. **弹窗重构**：从简单 Label 改为 VBoxContainer，按顺序排列：
   - 血量行（ProgressBar + 数字，无血量时隐藏）
   - 名字行（大字 Label）
   - 描述行（小字 Label，自动换行）
   - 状态行（HFlowContainer，每个状态一个可交互标签）
   - 标签行（HFlowContainer，每个标签一个可交互标签）

3. **可交互标签组件**：`interactable_tag.gd`
   - 继承 PanelContainer，内含 Label
   - 鼠标悬停 1 秒 或 左键单击 → 显示 tooltip
   - tooltip 内容：词条名称 + 详细解释（从 TagSystem/StatusEffectManager 读取）
   - tooltip 位置：标签下方或右侧，不超出屏幕

4. **对象类型适配**：
   - **玩家**：读取 Stats（血量/墨水）、当前状态、当前标签
   - **召唤物**：读取 SummonBase（血量/名字/描述）、状态、标签
   - **敌人**：读取敌人 Stats、状态、标签
   - **场景物体**（机关/建造物）：读取名字/描述、标签（如 FLAMMABLE）
   - **粒子**：读取元素类型、剩余时间、标签（如 BURNING）

5. **检查范围**：问号点击时，`intersect_point` 检测所有碰撞层，按距离排序，取最近的可检查对象

**依赖**：Phase 0.1（标签系统）+ Phase 0.2（状态效果管理器）

### Phase 1：召唤系统扩展（2-3天）

**目标**：从商鞅扩展到通用召唤框架

#### 1.1 召唤物基类

**新建文件**：`entities/summons/summon_base.gd`

```gdscript
class_name SummonBase extends CharacterBody2D

@export var data: SummonData  # 召唤物数据 Resource
var lifetime_timer: float
var current_health: float

func _ready():
    current_health = data.max_health
    lifetime_timer = data.lifetime
    # 注册到召唤管理器
    SummonManager.register(self)

func _physics_process(delta):
    lifetime_timer -= delta
    if lifetime_timer <= 0:
        despawn()
    _update_ai(delta)

func _update_ai(delta):
    # 子类重写：寻路 + 攻击逻辑
    pass

func take_damage(amount: float):
    current_health -= amount
    if current_health <= 0:
        despawn()

func despawn():
    SummonManager.unregister(self)
    queue_free()
```

#### 1.2 召唤数据 Resource

**新建文件**：`resources/summons/summon_data.gd`

```gdscript
class_name SummonData extends Resource
@export var id: StringName
@export var display_name: String
@export var character: String  # 显示的文字
@export var max_health: float
@export var damage: float
@export var move_speed: float
@export var lifetime: float
@export var attack_range: float
@export var attack_cooldown: float
@export var behavior: BehaviorType
@export var status_on_hit: StringName  # 攻击附带的状态效果

enum BehaviorType { ATTACK, DEFEND, SUPPORT, DOUBLE }
```

#### 1.3 召唤管理器

**新建文件**：`system/globals/summon_manager.gd`（Autoload）

```gdscript
var active_summons: Array[SummonBase] = []
var max_summons: int = 3

func register(summon: SummonBase):
    if active_summons.size() >= max_summons:
        active_summons[0].despawn()
    active_summons.append(summon)

func unregister(summon: SummonBase):
    active_summons.erase(summon)
```

#### 1.4 实现三个召唤物

| 召唤物 | 文件 | AI 行为 |
|--------|------|---------|
| 商鞅 | `entities/summons/shangyang.gd` | 从现有 `商鞅.gd` 提取，加寻路 |
| 哈基米 | `entities/summons/hami.gd` | 寻路到最近敌人 → 攻击 → 附加流血 |
| 牢大 | `entities/summons/lao.gd` | 寻路到最近敌人 → 肘击 → 附加眩晕 |

**AI 寻路**：复用敌人 AI 的 `NavigationAgent2D` 寻路逻辑

#### 1.5 修改 student.gd

### Phase 2：元素粒子系统（3-4天）

**目标**：实现火/水/风/雷/酸/油/冰/暗的粒子物理

#### 2.1 粒子基类

**新建文件**：`entities/particles/element_particle.gd`

```gdscript
class_name ElementParticle extends Area2D

@export var element_type: StringName  # "fire"/"water"/"wind" etc.
@export var lifetime: float = 5.0
@export var affected_by_gravity: bool = false
@export var affected_by_wind: bool = true
@export var damage_per_sec: float = 0.0

var velocity: Vector2 = Vector2.ZERO
```

#### 2.2 液体粒子（酸/油/水）

**新建文件**：`entities/particles/liquid_particle.gd`

**特殊行为**：
- 受重力影响，向下流淌
- 碰撞到物体时摊开（沿表面扩散）
- 按密度分层（油<水<酸）
- 残留机制（酸在表面残留 5-10s）

#### 2.3 雷电粒子

**新建文件**：`entities/particles/lightning_particle.gd`

**特殊行为**：
- 不受重力/风力影响
- 快速飞行到最近目标
- 优先 LIGHTNING_ROD > LIGHTNING_CONDUCTIVE
- 击中后传导给附近的 LIGHTNING_ROD
- 被传导过的对象不再传递

#### 2.4 粒子管理器

**新建文件**：`system/globals/particle_manager.gd`（Autoload）

**职责**：
- 管理所有活跃粒子
- 处理粒子间交互（火+风=扩散，水+火=熄灭等）
- 处理密度分层逻辑
- 风力场管理

#### 2.5 标签与粒子的联动

- 火粒子接触 FLAMMABLE → 添加 BURNING 标签
- 水粒子接触目标 → 添加 WET 标签 → 自动添加 LIGHTNING_ROD
- 油粒子接触目标 → 添加 OILED 标签 → 升级 FLAMMABLE
- 酸粒子接触 CORRODIBLE → 5秒后销毁目标

## 四、依赖关系

```
Phase 0 (基础设施)
  ├── 标签系统 ──────────────────┐
  ├── 状态效果管理器 ────────────┤
  ├── 状态效果 HUD ─────────────┤
  └── 问号检查系统升级 ──────────┤ ← 依赖标签 + 状态效果
                                 ↓
Phase 1 (召唤) ← 依赖标签系统 + 状态效果
Phase 2 (元素) ← 依赖标签系统 + 状态效果
Phase 3 (法术) ← 依赖标签系统 + 状态效果 + 粒子系统
Phase 4 (玩家能力) ← 依赖状态效果
Phase 5 (建造) ← 依赖标签系统
Phase 6 (整合) ← 依赖所有
```

**建议顺序**：Phase 0 → Phase 1 → Phase 4 → Phase 2 → Phase 3 → Phase 5 → Phase 6

理由：先做召唤（已有基础），再做玩家能力（独立），再做元素（复杂），再做法术（依赖元素），最后建造（最独立）。问号检查系统在 Phase 0 完成后即可投入使用，后续每个 Phase 都会扩展其可检查的对象类型。
